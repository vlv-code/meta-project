## Архитектурные принципы

1. **Разгрузка контекста (No Context Bloat):**  
   Корневой `AGENTS.md` содержит только базовые инварианты, принципы-ориентиры (North Stars), декларацию стека и навигационный протокол. Он всегда загружен в контекст [по документации], поэтому свободен от динамических логов и тяжелых описаний.
2. **Защита от архитектурных противоречий:**  
   В паспорте проекта фиксируются фундаментальные принципы и ориентиры решений (например: минимализм зависимостей, отказ от лишних абстракций, строгая типизация), блокирующие принятие чуждых проекту решений.
3. **Принцип неразрывной актуализации (Read + Opportunistic Refresh):**  
   Обращаясь к срезу мета-знаний перед работой, агент не просто пассивно читает его, но обязан закрывать найденные пробелы, фиксировать неточности и поддерживать целостность картины проекта.
4. **Безопасный аудит и обновление (Non-Destructive Update):**  
   Навык `init-meta-project` автоматически распознает уже существующую структуру meta-project в проекте, сохраняет все накопленные данные (`observations.md`, кастомные инварианты) и безопасно дооснащает проект новыми стандартами.
5. **Делегирование предметным навыкам стека:**  
   Вместо хардкода команд сборки и линтинга, паспорт подключает профильные навыки из оболочки агента (`python-pro`, `typescript-expert`, `docker-expert` и т.д.), несущие встроенное знание команд и стандартов.
6. **Машиночитаемые границы (Glob Boundaries):**  
   Зоны ответственности в `boundaries.md` заданы явными glob-паттернами путей, исключая субъективную интерпретацию агентом.

## Структура целевого репозитория

После инициализации в любом целевом проекте создается следующая стандартизированная структура:

```text
<корень_проекта>/
├── AGENTS.md                          # Паспорт-навигатор (North Stars, стек, протокол актуализации, навыки)
└── .agents/
    ├── project_knowledge/             # Срезы мета-знаний (подгружаются по требованию)
    │   ├── architecture.md            # Архитектурные основы и связи компонентов
    │   ├── boundaries.md              # Машиночитаемые зоны (зеленая, желтая, красная зоны)
    │   ├── weak_spots.md              # Известные грабли, риски и техдолг
    │   ├── observations.md            # Накопительный лог находок агентов (по категориям)
    │   └── tasks.md                   # Реестр текущих задач и чеклист координации
    ├── skills/                        # Предустановленные навыки репозитория
    │   ├── ground-meta-project/       # Аварийное заземление и рекалибровка контекста
    │   │   └── SKILL.md
    │   ├── record-observation/        # Навык атомарной записи в observations.md
    │   │   └── SKILL.md
    │   └── sync-architecture/         # Навык актуализации architecture.md
    │       └── SKILL.md
    └── team/                          # (Опционально) Команда субагентов (управляется manage-meta-project)
        ├── agent-<роль>/
        │   ├── profile.md             # Паспорт роли и телеметрия вызовов
        │   ├── notes.md               # Приватные рабочие заметки роли
        │   └── system_prompt.md       # Стартовый системный промпт роли
        └── archive/                   # Безопасно архивированные роли (через decommission-meta-project)
```

## Компоненты репозитория Meta-Project

- **`templates/`**:
  - `templates/AGENTS.md` — эталонный шаблон проектного паспорта с принципами-ориентирами (North Stars) и протоколом неразрывной актуализации.
  - `templates/global/AGENTS.md` — универсальный эталонный манифест для глобальной конфигурации сред агентов (First-Contact Rule, Default Deny, Circuit Breaker).
  - `templates/project_knowledge/` — заготовки файлов для каталога мета-знаний проекта (`architecture.md`, `boundaries.md`, `weak_spots.md`, `observations.md`, `tasks.md`).
  - `templates/team/` — заготовки паспорта роли (`profile.md`), изолированных приватных заметок (`notes.md`) и системного промпта (`system_prompt.md`).
- **`skills/`**:
  - `skills/init-meta-project/` — автономный навык с поддержкой двух режимов: безопасного аудита/обновления существующего `meta-project` без потери данных или первичной двухпроходной инициализации чистого репозитория с обязательным чек-листом чтения ядра (`Core Inspection Checklist`), регламентом интерактивного интервью и атомарной выгрузкой (`In-Memory Synthesis Flush`).
  - `skills/manage-meta-project/` — навык формирования, аудита и оркестровки команды специализированных субагентов проекта (.agents/team/) с адаптивной матрицей компетенций, контролем неактивных ролей (Role Pruning) и регламентами User-Mediated Handoffs.
  - `skills/decommission-meta-project/` — навык безопасной декоммиссии, изменения масштаба и архивации ролей команды агентов (.agents/team/) в `.agents/team/archive/` с финализацией телеметрии, синхронизацией корневого `AGENTS.md` и переназначением повисших задач без потери данных.
  - `skills/ground-meta-project/` — навык принудительного заземления и зум-аута: экстренная остановка правок, перечитывание канонических источников (AGENTS.md, роль, границы, карта) и возврат агента в рабочий коридор.
  - `skills/record-observation/` — навык категоризированной записи наблюдений в `observations.md` с контролем дубликатов и триггерами компакции памяти.
  - `skills/sync-architecture/` — навык структурного анализа манифестов и актуализации карты компонентов.
- **`scripts/`**:
  - `scripts/check_boundaries.py` — автономный CLI гейта границ (Boundary Gate) на Python stdlib, обеспечивающий принудительный машинный контроль зон (Green/Yellow/Red) и инварианта Default Deny локально и в GitHub Actions CI (поддерживает `--audit-tree` для 100% покрытия дерева и `--install-hook` для настройки pre-commit).
  - `scripts/compact_memory.py` — утилита защиты контекста (Context Rot Shield), автоматически архивирующая разросшиеся таблицы наблюдений (>20 записей) и выполненные задачи в `.agents/project_knowledge/archive/`, с сохранением постоянных инвариантов `[pin]`.
  - `scripts/sync_templates.py` — утилита инъекции канонических шаблонов во встроенные скиллы и валидации 1-в-1 паритета навыков между `skills/` и `.agents/skills/` (режим `--check` для CI).
- **`docs/`**:
  - `docs/decisions_and_roadmap.md` — журнал архитектурных решений (ADR #1–#8 + Polyglot Monorepo Incident) и перспективный роадмап.
  - `docs/test_report_alpha_skill.md` — эмпирический отчет по итогам серии тестирований (Тесты 1–6) на тестовом бот-сервисе.
  - `docs/temporary_overrides.md` — временные калибровки правил.

## Быстрый старт (Quickstart)

### 1. Подготовка глобальной агентной обвязки (Universal First-Contact Setup)
Чтобы автономные агенты автоматически находили и применяли паспорта Meta-Project (`AGENTS.md`) и срезы знаний в любом репозитории, настройте окружение с помощью `templates/global/AGENTS.md`:

| Агентная среда | Путь к глобальной конфигурации | Рекомендуемое действие |
| :--- | :--- | :--- |
| **Google Antigravity / Gemini CLI** | `~/.gemini/GEMINI.md` | Дописать содержимое `templates/global/AGENTS.md` |
| **Claude Code** | `~/.claude/CLAUDE.md` | Дописать содержимое `templates/global/AGENTS.md` |
| **Cursor / Windsurf** | Global User Rules / `.cursorrules` | Вставить содержимое `templates/global/AGENTS.md` |
| **Открытые агентные раннеры** | `~/AGENTS.md` | Скопировать `templates/global/AGENTS.md` |

### 2. Подключение навыков к среде агента
Скопируйте навыки meta-project (`init-meta-project`, `manage-meta-project`, `decommission-meta-project`, `ground-meta-project`) в каталог навыков вашей агентной среды:
- Для Google Antigravity: `~/.gemini/config/skills/<skill-name>`
- Или используйте локально в составе вашего набора инструментов.

### 3. Инициализация в проекте
Перейдите в корень любого целевого репозитория и дайте агенту команду:
```text
Подготовь репозиторий к работе с агентами с помощью навыка init-meta-project
```

Агент выполнит:
1. Анализ манифестов и файловой структуры.
2. Изучение критических компонентов (Core Inspection Checklist: БД, API, Docker, UI/валидация).
3. Создание корневого `AGENTS.md` и каталога мета-знаний `.agents/project_knowledge/`.
4. Установку локальных навыков репозитория (`record-observation`, `sync-architecture`).

### 4. Оркестровка и декоммиссия команды агентов (опционально)
Для развертывания и координации ролей специализированных субагентов:
```text
Сформируй команду агентов с помощью навыка manage-meta-project
```
Для безопасной архивации или масштабирования ролей без потери данных:
```text
Законсервируй команду агентов с помощью навыка decommission-meta-project
```

### 5. Принудительное заземление и зум-аут (Emergency Grounding)
Если агент потерял контекст, делает спекулятивные правки или выходит за рамки роли:
```text
Заземли агента с помощью навыка ground-meta-project
```

### 6. Режимы развертывания: Открытый стандарт vs Невидимый оверлей

Meta-Project поддерживает два сценария использования:
- **Shared Repo-Level (Командный / Открытый стандарт):**  
  `AGENTS.md` и `.agents/` коммитятся в Git. Правила, карта архитектуры и реестр рисков разделяются между всеми разработчиками, агентами и CI-пайплайнами.
- **Invisible Overlay (Личный пульт для чужих/рабочих репозиториев):**  
  `AGENTS.md` и `.agents/` автоматически заносятся в локальный `.git/info/exclude` целевого проекта. Агент получает полный доступ к мета-знаниям на вашем ПК, но Git остается кристально чистым, не создавая лишних коммитов в чужих проектах.

## Тестирование и валидация

Проект содержит автоматические тесты целостности навыков, YAML frontmatter, шаблонов и канонической структуры:

```bash
python -m unittest discover -s tests -p "test_*.py" -v
```

Тесты не имеют внешних зависимостей и работают на любой системе с Python 3.10+.

## Участие в разработке (Contributing)

Meta-Project активно пилится, и мы открыты для любых предложений и помощи от сообщества! Будем особенно рады вкладу по направлениям:
- **Тестирование на реальных проектах:** прогон `init-meta-project` и ролевых команд на проектах с разными стеками (Rust, Go, Node.js, C/C++, мобильная разработка, микросервисы) и разбор узких мест.
- **Новые инварианты и грабли:** пополнение реестра наблюдений (`observations.md`) и калибровка шаблонов границ (`boundaries.md`) для редких краевых случаев рантайма.
- **Развитие CLI и автоматизации:** расширение zero-dependency утилит (`check_boundaries.py`, `compact_memory.py`, `sync_templates.py`) или создание адаптеров для других агентных сред.
- **Документация и переводы:** улучшение гайдов, исправление неточностей, добавление практических сценариев.

Перед созданием Pull Request ознакомьтесь с [CONTRIBUTING.ru.md](CONTRIBUTING.ru.md).

Все изменения версий фиксируются в [CHANGELOG.md](CHANGELOG.md).
