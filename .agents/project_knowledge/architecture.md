# Architectural Foundations: Meta-Project

## 1. High-Level System Overview
- **Project Type:** Specification, templates, and agentic context & knowledge framework (Agentic Context & Knowledge Framework).
- **Core Stack:** Python 3.10+ (stdlib `unittest`), Markdown, GitHub Actions CI.
- **Architectural Principle:** Zero runtime dependencies & Default Closed Tooling. All validation checks and templates operate autonomously using standard library Python; third-party tools require explicit opt-in.

## 2. Key Components and Data Flows
- **Templates (`templates/`):**
  - `templates/AGENTS.md` — canonical project passport with North Stars and opportunistic refresh protocol.
  - `templates/global/AGENTS.md` — global user-level passport template for `~/.gemini/AGENTS.md` or home directory environments.
  - `templates/project_knowledge/` — meta-knowledge slices (`architecture.md`, `boundaries.md`, `weak_spots.md`, `observations.md`, `tasks.md`).
  - `templates/team/` — role profile templates (`profile.md`), private notes (`notes.md`), and system prompts (`system_prompt.md`).
  - `templates/reports/` — canonical report validation schemas (`init_report.json`, `manage_report.json`) for machine-readable audit trails.
- **Procedural Skills (`skills/`):**
  - `skills/init-meta-project/` — two-pass initialization and audit of agent environment in any repository with Step 0 Host Runtime Self-Identification (Anti-Anchoring Invariant).
  - `skills/manage-meta-project/` — formation, audit, and scale-adaptive orchestration of specialized agent roles (Tier 0 Duo, Tier 1 Compact Trio, Tier 2+ granular teams) with pre-flight report intake and anti-anchoring runtime safeguards. Wave G slim: 394 → 220 lines; team templates ship as `resources/` (byte-copies of `templates/team/*`, sync-managed, MISSING_RESOURCE contract) — the init-P2 resource pattern generalized to a second skill.
  - `skills/decommission-meta-project/` — non-destructive decommissioning, resizing, and archiving of agent roles.
  - `skills/ground-meta-project/` — emergency grounding, runaway edit halt, and context recalibration.
  - `skills/scan-meta-project/` — integrity inspection, boundary coverage audit, and backfilling meta-knowledge without re-init.
  - `skills/tune-meta-project/` — git friction diagnostics, role topology tuning, and non-bloating North Star crystallization.
  - `skills/update-meta-project/` — non-destructive upstream updating from GitHub or local cache with local_repo_data preservation.
  - `skills/record-observation/` — standardized logging of quirks and solutions into `observations.md` via `record_obs.py`.
  - `skills/sync-architecture/` — structural analysis and generation of the architectural slice.
- **Automation Scripts (`scripts/`):**
  - `scripts/check_boundaries.py` — zero-dependency CLI enforcing Default Deny and responsibility zones via Git diff (bilingual Russian/English zone headers, `--audit-tree` for 100% path coverage, `--diff` for base revision comparison). Fail-closed git queries (unresolvable revisions abort with an error, never an empty 'Clean'), `--no-renames` so renamed Red Zone paths are still checked, `--repo-root` scoping for all git operations, and `--install-hook` deploying a dispatcher pre-commit hook (legacy hook preserved as `pre-commit.legacy-meta` and executed as a separate process; worktree/core.hooksPath support; explicit conflict reporting for external hook managers).
  - `scripts/compact_memory.py` — memory compaction utility rotating oversized observation tables and completed tasks into `.agents/project_knowledge/archive/`, permanently preserving `[pin]` invariant entries with cross-platform file locking (`msvcrt` / `fcntl`) and index-based row retention. Re-homes orphaned data rows recorded past the table/archive NOTE back into the table, collapses duplicate archive NOTEs, and keeps `--dry-run` strictly read-only (no `.lock` files).
  - `scripts/sync_templates.py` — zero-dependency template injection and skill parity synchronizer (`--check`, `--write` with fail-closed non-zero exit on unrecoverable errors and post-write re-verification, `--global-skills` for global harness cache sync, and byte-exact LF mirror writing and drift detection).
  - `scripts/record_obs.py` — zero-dependency CLI utility inserting validated, escaped observation rows INTO the `observations.md` table (before trailing text/NOTEs) with cross-platform file locking, atomic temp-file writes, exact-duplicate suppression, and qualified `--actor-id` attribution.
  - `scripts/verify_identity.py` — zero-dependency CLI validator for multi-harness identity registry (`.agents/meta-project.json`, schema 1.0.0 and 1.1.0 by value), scenario configuration, and role profile bindings. Enforces actor_id harness↔installation matching, host runtime detection (`detect_host_harness`) with anti-anchoring mismatch warnings, installation/binding status enums, structured diagnostics for malformed roots, valid team-less base registries, and separates lookup from admission: `--actor` admits only ACTIVE bindings on ACTIVE installations (`evaluate_actor_admission`).
  - `scripts/inspect_meta_project.py` — zero-dependency CLI survey utility evaluating repository state across 8 canonical states (incl. `CONTEXT_UNRESOLVED` for unknown runtime context — never silently adopting any active installation; anti-anchoring remediation guidance without registry copying), host environment auto-detection (`detect_host_harness`) supporting `--harness auto` and host mismatch warnings, requiring the project passport, boundaries, and a registry VALID per `verify_identity` for HEALTHY states, scoping the roles capability to the target installation, resolving worktree `git_toplevel`/hooks directories correctly, calculating the 5-dimension Capability Matrix, enforcing zero-write inspection, and emitting `--facts-digest` (byte-stable JSON fingerprint: state + per-slice sha256 + capabilities; Wave G — a stashed digest substitutes for re-reading unchanged slices, ground consumes it).
  - `scripts/manage_reports.py` — zero-dependency CLI and library for creating, validating, and locating initialization (`init`) and management (`manage`) reports in `.agents/reports/<installation_id>/` with atomic file writes, run_id overwrite refusal, RELATIVE `latest.json` pointers (repository-copy isolation), latest-attempt surfacing (corrupted latest never silently replaced by older valid), SHA-256 `input_fingerprints` of essential inputs (registry/boundaries/passport) for staleness detection incl. uncommitted changes, project identity resolved from the local registry (no hardcoded default), and the `evaluate_manage_intake` admission engine separating format validation from intake authorization (init → manage contract). Wave F hardening: path-safe identifiers (`installation_id`/`init_run_id`/`report_type`), 40-hex `commit_sha` before git argv, fail-closed `git_state_error` → stale/suspect, deterministic latest (mtime+name) with O_EXCL overwrite guard, fingerprints required for completed init/manage reports, rename-aware staleness, exact schema_version set.
  - `scripts/update_meta_project.py` — zero-dependency managed update engine (check/plan/apply/restore): SHA-pinned single-revision bundles (`git cat-file`, CRLF-immune), three-way merge with `local_repo_data` block preservation (HTML + code-form markers), lock v2 (base/installed/target), plan-pins-apply TOCTOU verification, atomic journaled apply with lock rollback in restore, offline cache with origin cross-verification + per-cache sha256 manifest (SEC-2), three-layer containment guard on every written/read path incl. symlink refusal (SEC-1), engine operation lock serializing apply/restore (`ENGINE_BUSY`), actor admission, project Red-zone ∪ `--protect` perimeter, runtime-layout target mapping, `--adopt-existing` sha-match adoption, plan summary mode, manifest fallback (`manifest.json` → `templates/release_manifest.json`), `check_status` field with documented rc contract, EOL-normalized installed-content comparison (autocrlf smudge = `eol_normalized` diagnostic, never false drift; cache/origin verification stays byte-exact — Wave G), dead symbols removed (U4/U10), and stderr notice when core instructions or skills are updated prompting harness session reload.

## 3. Data and State Invariants
- **Specification Format:** Markdown with YAML frontmatter for skills; Markdown tables for observations; path glob patterns for responsibility zones.
- **Contract Stability:** File names of knowledge slices and templates are fixed in integrity tests.
  - .github/workflows/release.yml — automated release pipeline triggered on * tag push with fail-fast tag/manifest/CHANGELOG parity, git archive source/dist packaging, and automated GitHub Release publishing with prerelease classification.
- **Security Policy Invariant:** Security gate scripts (`scripts/check_boundaries.py`), boundary policy definitions (`*boundaries.md`), and CI/CD configurations are strictly enforced in Red Zone and guarded via `.github/CODEOWNERS`.

## 4. End-to-End Data Flows (Pre-Flight Flow Tracing)
Every multi-tier feature or modification touching agent orchestration, templates, or skills must map the lifecycle across framework layers:

```
[User Request / Goal] ➔ [Intake Dispatcher / agent-dev-lead] ➔ [Stack Skills / Subagents] ➔ [Templates / Knowledge Slices / Integrity Tests] ➔ [Verified Delivery]
```
- **Primary Data Flow 1 (Scaffolding):** User prompt ➔ `init-meta-project` ➔ In-Memory Analysis ➔ Materialized `.agents/` + `AGENTS.md` ➔ `test_integrity.py` validation.
- **Primary Data Flow 2 (Orchestration):** User request ➔ `agent-dev-lead` (fast-track) or decomposition ➔ domain role / subagent ➔ telemetry logging in `profile.md` + opportunistic refresh in `project_knowledge/`.
- **Primary Data Flow 3 (Tier 0 Duo Execution):** User request ➔ `agent-dev-lead` (TDD with adversarial negative checks) ➔ `agent-quality-guardian` / `agent-inspector-guardian` (integrity, test suite, git hygiene, commit).
- **Primary Data Flow 4 (Scenario Agreement & Report Handoff):** User prompt ➔ `init-meta-project` Survey (Zero-Write) ➔ Explicit User Scenario Agreement ➔ `.agents/meta-project.json` (Scenario & Identity) + `.agents/reports/<installation_id>/init/<init_run_id>.json` (via `scripts/manage_reports.py`) ➔ `manage-meta-project` Report Intake & Staleness Check ➔ Topology Resolution & Team Materialization ➔ `.agents/reports/<installation_id>/manage/<manage_run_id>.json`.
- **Single Source of Truth:** `templates/` and canonical `skills/` in the repository root are authoritative; `.agents/team/` and `.agents/skills/` reflect active deployed instances.
- **Plugin Packaging (Wave P):** three manifests (`.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, root `plugin.json` per Agent Plugins 1.0.0) expose `skills/` to Claude Code / Agent Plugins / skills.sh channels; version single-source = `templates/release_manifest.json.framework_version`, locked by `tests/test_pwave_p.py` (skip-guarded locks); `main` is the clean distribution branch (no `.agents/`), `dev` is the dogfooding branch — install channels resolve `main`.
- **SHA-bound Red-Zone sanctions (Wave H/P):** `.github/red-zone-sanction.json` (itself Red-mapped) carries base_sha + authorized_by + paths; the trusted-base gate admits listed Red violations while the bound revision is HEAD; expires with the base — every new sanctioned push re-issues it.

## 5. Design Patterns
- **Separation of Concerns:** Division of static passport rules (`AGENTS.md`), dynamic meta-knowledge slices (`project_knowledge/`), and procedural actions (`skills/`).
- **Opportunistic Knowledge Refresh:** Protocol for continuous knowledge refinement upon every consultation.
