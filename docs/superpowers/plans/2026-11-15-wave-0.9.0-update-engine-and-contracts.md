**Goal:** Turn `update-meta-project` into a managed, deterministic, crash-recoverable update of the installed framework, backed by explicit release/component contracts (manifest vs lock) — without requiring published releases for SHA pinning.

**Architecture:** A stdlib engine (`scripts/update_meta_project.py`) resolves a ref to an exact commit SHA, materializes the ENTIRE component set from that single SHA (upstream git or integral cache), computes a three-way merge plan against the installed lock, applies atomically with a journal and restore mode, and records an `update` report through the existing report engine. Skills keep only conflict analysis and user interaction. A canonical release manifest (`templates/release_manifest.json`) is the single composition description shared by init and update.

**Tech Stack:** Python 3.10+ standard library only (`argparse`, `json`, `hashlib`, `subprocess`, `pathlib`, `tempfile`, `shutil`, `unittest`), Git CLI, Markdown.

**Spec:** `docs/НЕ ОБРАБОТАННЫЕ БУДУЩИЕ ИЗМЕНЕНИЯ meta-project.md` — sections §1–§5, §9, §10, the versioning decisions from the embedded dialogue, and the six reviewer corrections of 2026-11-15 (SHA pinning without releases; tag after acceptance; manifest≠lock; Red-Zone sanction stays open; role assignment vs validation; legacy-path transition).

## Global Constraints

- **Zero-dependency:** Python 3.10+ stdlib + Git CLI only.
- **SHA pinning without releases:** the engine resolves a ref (branch/tag/SHA) to ONE exact commit SHA and fetches every component from that SHA. Mixing files from different revisions in one update is prohibited. On network failure, switching to an INTEGRAL cached bundle is allowed with its origin declared; a partial cache is refused.
- **Version line:** existing tag `v1.0.0-alpha.1`; the next release is `v1.0.0-alpha.2`; "0.9.0" is the internal wave codename only. The tag and GitHub Release are published by the steward ONLY after Phase F acceptance. Development and testing use fixed SHAs and local test bundles.
- **Manifest ≠ lock:** the release manifest describes ALL available components, their kinds and dependencies, supported schemas, and migrations. The project lock (`.agents/framework-lock.json` in TARGET repositories) records the actually-installed SUBSET. The minimal scaffold (3 embedded skills + core scripts) remains a valid installation. Component count is not frozen: new shared modules enter as dependencies of components.
- **Red Zone sanction — EXPLICITLY OPEN:** user confirmation + local `--allow-red-zone` is a temporary LOCAL mechanism and does NOT prove permission in CI. The engine REFUSES automated changes to protected components and reports a manual path until a sanctioned mechanism exists (deferred audit §2 item; does not block other work).
- **Role assignment vs validation:** the session or user assigns the role; `verify_identity` validates the binding and admission. The registry never auto-adopts a different active record on the agent's behalf.
- **Legacy location transition:** canonical runtime location is `scripts/`. Legacy `.agents/scripts/` is supported only via EXPLICIT migration. When two divergent copies of a utility exist, halt with a report — never silently take the first found.
- **No new hooks, no plugin system, no SessionStart automation; no background updates without an explicit user request.**
- **Reuse, never duplicate:** canonical validators (`verify_identity`, `evaluate_manage_intake`, `inspect_meta_project`) are the only identity/admission/report authority; new scripts call them.
- **Non-destructive:** knowledge slices, role notes, telemetry, active installations, and local adaptations (inside OR outside `local_repo_data` markers) are preserved or surfaced as explicit conflicts — never silently replaced.
- **check/plan modes are strictly read-only:** zero writes to the project, reports, cache, and lock files (zero-write invariant, snapshot-verified).
- **Atomicity & recovery:** per-file atomic replace, operation journal, crash restore of ONLY the engine's own changes; third-party edits made during apply are detected and never clobbered.
- **House commit policy:** tasks end with verification steps; conventional commits are issued by `agent-github-steward` at wave close (per-series precedent), not per-task.
